# フェーズ2 詳細実装計画書

## 目的
UI/UXの体験品質を向上させ、状態設計・マイクロインタラクション・パフォーマンス最適化を実装する

## 対象範囲
- 状態設計（エラー・空・ローディング状態の統一デザイン）
- マイクロインタラクションシステム（ホバー・フォーカス・アクティブ・トランジション）
- スケルトンUI・プログレッシブ表示・体感パフォーマンス改善
- リグレッション防止テスト設計・実装

## 前提条件
- フェーズ1が完了し、デザイントークンシステム・アクセシビリティ基盤が構築済み
- Python 3.11+ 環境
- Streamlit 1.35.0
- 既存のテストフレームワーク（pytest）

## 実装ステップ（合計12ステップ）

### ステップ 1: 状態設計システムの基本設計（0.5日）
**目的**: エラー・空・ローディング状態の統一デザインシステムを設計
**作業内容**:
- 状態タイプの定義と分類（エラー、警告、成功、情報、空、ローディング、アイドル）
- 各状態の視覚言語（アイコン、色、タイポグラフィ、レイアウト）の統一
- アクション導線の設計（再試行、代替手段、サポートリンクなど）
- アクセシビリティ考慮（スクリーンリーダーへの適切な発表、フォーカス管理）
**成果物**:
- `docs/state_design_system.md`（設計書）
- 状態コンポーネントのインターフェース定義

### ステップ 2: 状態コンポーネントの基本実装（1日）
**目的**: 基本的な状態表示コンポーネントを実装
**作業内容**:
- エラーコンポーネント（エラーメッセージ、再試行ボタン、サポートリンク）
- 空状態コンポーネント（イラスト・アイコン、説明文、プライマリCTA、セカンダリアクション）
- ローディングコンポーネント（スピナー・プログレスバー、キャンセル可能オプション、推定時間表示）
- 全コンポーネントでデザイントークンを使用し、アクセシビリティを確保
**成果物**:
- `retro_radio/ui/state_components.py`
- 基本的な状態表示のStorybookストーリー（または同様のドキュメント）

### ステップ 3: 状態コンポーネントのバリエーション実装（1日）
**目的**: 状態コンポーネントのサイズ・バリエーションを実装
**作業内容**:
- バナーバージョン（ページトップ表示用）
- インラインバージョン（フォームフィールド横など）
- モーダルバージョン（ダイアログ内表示）
- フルスクリーンバージョン（ページ全体を覆うエラー・メンテナンス表示）
- コンパクト・レギュラー・ラージサイズバリエーション
**成果物**:
- `state_components.py` にバリエーション実装
- 各バリエーションの使用例ドキュメント

### ステップ 4: マイクロインタラクション設計システム構築（0.5日）
**目的**: ホバー・フォーカス・アクティブ・トランジションの体系的設計
**作業内容**:
- インタラクション状態の定義（デフォルト・ホバー・フォーカス・アクティブ・ディセーブル・訪問済みリンク）
- 各状態の視覚変化（色変化・スケール変化・シャドウ変化・ボーダー変化）
- トランジション設計（期間・イージングカーブ・プロパティ）
- 音apticフィードバックの検討（Web Audio API 使用の可能性）
**成果物**:
- `docs/micro_interactions.md`（設計書）
- トークンシステムへのインタラクション状態追加設計

### ステップ 5: ボタンマイクロインタラクション実装（1日）
**目的**: ボタンのマイクロインタラクションを実装
**作業内容**:
- ホバー時の色変化・スケール変化・シャドウ追加
- フォーカス時のアウトライン・リング表示（WCAG 対応）
- アクティブ時のプレスエフェクト（スケール縮小・色濃淡）
- ディセーブル状態の視覚表現（不透明度・カーソル変更）
- ローディング状態のインジケータ表示（スピナー・テキスト変更）
- トランジション期間：150-250ms、イージング：cubic-bezier(0.25, 0.46, 0.45, 0.94)
**成果物**:
- `styles.py` またはトークンベースのスタイルにマイクロインタラクション実装
- ボタンの全状態をカバーするテストケース追加

### ステップ 6: フォーム要素マイクロインタラクション実装（1日）
**目的**: フォーム要素（入力・選択・スライダーなど）のマイクロインタラクションを実装
**作業内容**:
- 入力フィールド：フォーカス時のボーダー変化・シャドウ・ラベルアニメーション
- チェックボックス・ラジオボタン：チェック時のアニメーション・状態変化
- セレクトボックス：ドロップダウン表示・オプションホバー効果
- スライダー：つまみのホバー・ドラッグ時の視覚フィードバック
- トースト・スナックバー：表示・非表示時のスライドイン・フェードアニメーション
**成果物**:
- フォームコンポーネントのマイクロインタラクション実装
- 状態変化時のアクセシビリティ確保（フォーカス管理・スクリーンリーダー発表）

### ステップ 7: ナビゲーション・トランジションマイクロインタラクション実装（0.5日）
**目的**: ナビゲーション・ページ遷移のマイクロインタラクションを実装
**作業内容**:
- タブ切り替え時のインジケータアニメーション
- アコーディオンの開閉アニメーション
- モーダルのフェードイン・スケールアニメーション
- ドロワー・サイドバーのスライドインアニメーション
- ページ遷移時のフェード・スライド効果（SPA風体験）
**成果物**:
- ナビゲーションコンポーネントのトランジション実装
- prefers-reduced-motion メディアクエリ対応

### ステップ 8: スケルトンUI実装（1日）
**目的**: コンテンツ読み込み中のスケルトンUIを実装
**作業内容**:
- ページレイアウトを模倣したグレースケールのプレースホルダー
- テキストブロックのスケルトン（行の高さ・幅を模倣）
- 画像・アバターのスケルトン（円形・長方形・正方形バリエーション）
- リストアイテムのスケルトン（横並び・縦並びレイアウト対応）
- アニメーション効果：パルスまたはグラデーションスライド（WCAG 配慮）
**成果物**:
- `retro_radio/ui/skeleton_components.py`
- 各レイアウトパターンのスケルトン実装
- ローディング状態との統合

### ステップ 9: プログレッシブ表示戦略実装（1日）
**目的**: 重要度に基づく段階的コンテンツ表示を実装
**作業内容**:
- Critical CSS のインライング（上部表示コンテンツのスタイル）
- フォールトフォールドコンテンツの遅延読み込み（Intersection Observer 使用）
- 低優先度画像のLazy Loading（loading="lazy"属性またはJS実装）
- フォントのFont Loading Strategy（FOIT vs FOUT vs 段階的レンダリング）
- 非同期コンテンツのプレースホルダー・スケルトン表示
**成果物**:
- `utils/progressive_loading.py`（プログレッシブ読み込みユーティリティ）
- `main.py` またはレイアウトコンポーネントへの統合
- LCP（Largest Contentful Paint）改善を目的とした実装

### ステップ 10: 体感パフォーマンス改善テスト実装（0.5日）
**目的**: 体感パフォーマンスの指標を測定・テストする基盤を構築
**作業内容**:
- LCP・CLS・FID のブラウザAPIを使用した測定実装
- カスタムメトリクス：UIスレッドブロック時間・入力遅延・アニメーションジャンク
- 人工的な遅延シミュレーションツール（開発時の体感テスト用）
- パフォーマンス予算の設定とアラート機能
**成果物**:
- `tests/performance/test_vital_metrics.py`
- パフォーマンス測定ダッシュボード（開発用）
- CI へのパフォーマンス回帰テスト組み込み検討

### ステップ 11: 状態・マイクロインタラクションの統合テスト実装（1日）
**目的**: 状態コンポーネントとマイクロインタラクションの組み合わせをテスト
**作業内容**:
- エラー状態からのリカバリーフロー（ボタンホバー・フォーカス・クリックのテスト）
- 空状態からのオンボーディングフロー（CTAのインタラクションテスト）
- ローディング状態のインタラクション（キャンセルボタン・プログレス操作）
- ロングタップ・ダブルタップなどのジェスチャー対応検討（タッチデバイス）
- キーボードのみでの状態遷移・インタラクションテスト
**成果物**:
- `tests/integration/test_state_interactions.py`
- エンドツーエンドの状態フローテスト
- アクセシビリティ観点での統合テスト

### ステップ 12: リグレッション防止のための包括的テストスイート構築（1日）
**目的**: フェーズ2の変更を守るためのテストスイートを完成させる
**作業内容**:
- ビジュアルリグレッションテストの拡張（状態・マイクロインタラクション対応）
- アクセシビリティテストの拡張（新コンポーネント・状態対応）
- パフォーマンステストのベースライン確立
- コンポーネントライブラリのドキュメント化・ストーリーブック連携
- リリース前チェックリストの自動化
**成果物**:
- `tests/visual/test_state_components.py`
- `tests/visual/test_micro_interactions.py`
- テストレポート自動生成スクリプト
- リリースガイドドキュメントの更新

## 成功基準
- すべてのインタラクティブ要素にホバー・フォーカス・アクティブ・ディセーブル状態が実装されていること
- エラー・空・ローディング状態が統一されたデザイン言語で表示されていること
- スケルトンUIがローディング時間を短縮して体感されていること
- マイクロインタラクションが150-250msの適切なトランジションで実装されていること
- WCAG 2.1 AA 基準を引き続き満たしていること（フォーカス可視性・コントラスト比）
- LCP が 2.5秒以下、CLS が 0.1以下、FID が 100ms以下を目標とする
- 新しい状態・インタラクションを追加する際にビジュアルテストが変更を検知できること
