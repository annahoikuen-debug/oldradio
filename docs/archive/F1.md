# フェーズ1 詳細実装計画書

## 目的
デザインシステムの基盤を構築し、一貫した視覚言語とアクセシビリティ基準を確立する

## 対象範囲
- デザイントークンシステム（色、スペーシング、タイポグラフィ）
- アクセシビリティ基盤（フォーカス、コントラスト、スクリーンリーダー対応）
- リグレッション防止テスト設計・実装

## 前提条件
- Python 3.11+ 環境
- Streamlit 1.35.0
- 既存のテストフレームワーク（pytest）

## 実装ステップ（合計12ステップ）

### ステップ 1: デザイントークン構造設計（0.5日）
**目的**: トークン階層構造（primitive → semantic → component）を定義
**作業内容**:
- `design_tokens/` ディレクトリ作成
- `primitives/`、`semantics/`、`components/` サブディレクトリ作成
- JSON Schema 形式でトークン構造定義
- 色トークンのプリミティブ定義（ブランドカラー、グレースケール、状態カラー）
**成果物**: 
- `design_tokens/primitives/color.json`
- `design_tokens/primitives/spacing.json`
- `design_tokens/primitives/typography.json`

### ステップ 2: プリミティブトークン実装（0.5日）
**目的**: 色・スペーシング・タイポグラフィのプリミティブトークンを実装
**作業内容**:
- 色プリミティブ: ブランドカラー（#1f6feb 等）、グレースケール、状態カラー（成功/警告/エラー）
- スペーシングプリミティブ: 4px 基準の 8段階スケール（4, 8, 12, 16, 24, 32, 48, 64）
- タイポグラフィプリミティブ: フォントファミリー、フォントサイズ、行高、文字間
**成果物**:
- JSON ファイルに実際の値を設定
- 例: `{"color-brand-500": "#1f6feb", "color-gray-900": "#1a1a1a"}`

### ステップ 3: セマンティックトークン実装（1日）
**目的**: コンテキストに応じた意味付けトークンを作成
**作業内容**:
- インタラクティブ状態用トークン（ボタン、リンク、フォーム要素）
- 背景・フォアグラウンド用トークン
- 状態フィードバック用トークン（成功/警告/エラー/情報）
- ダークモード対応のためのトークンマッピング
**成果物**:
- `design_tokens/semantics/color.json`
- `design_tokens/semantics/spacing.json`
- 例: `{"color-interactive-primary": "{color-brand-500}", "color-background-base": "{color-gray-50}"}`

### ステップ 4: コンポーネントトークン実装（1日）
**目的**: 特定コンポーネント用のトークンを定義
**作業内容**:
- ボタン用トークン（サイズ別、状態別）
- フォーム用トークン（入力フィールド、ラベル、ヘルプテキスト）
- ナビゲーション用トークン（ヘッダー、フッター、サイドバー）
- カード・パネル用トークン
**成果物**:
- `design_tokens/components/button.json`
- `design_tokens/components/form.json`
- 例: `{"button-primary-bg": "{color-interactive-primary}", "-button-primary-padding-y": "{spacing-4}"}`

### ステップ 5: トークン変換・インジェクションシステム実装（1日）
**目的**: JSON トークンを CSS カスタムプロパティまたは CSS-in-JS に変換するシステムを構築
**作業内容**:
- Python スクリプトで JSON トークンを読み込み、CSS 変数形式で出力
- Streamlit カスタムコンポーネントまたは CSS インジェクション機構を実装
- ビルド時・ランタイム両方に対応可能な設計
**成果物**:
- `utils/design_tokens.py`（トークン読み込み・変換モジュール）
- `styles/generated.css`（自動生成される CSS ファイル）
- ビルドスクリプト（`npm run build:tokens` または Python スクリプト）

### ステップ 6: 基礎スタイルシートへのトークン統合（0.5日）
**目的**: 既存スタイルシートにデザイントークンを適用
**作業内容**:
- 既存の `retro_radio/ui/styles.py` をトークンベースにリファクタリング
- ハードコードされた値をすべてトークン参照に置換
- メディアクエリ・ダークモード・ハイコントラスト対応を維持
**成果物**:
- リファクタリング済み `styles.py`
- ハードコード値ゼロを目標（可能な限り）

### ステップ 7: アクセシビリティ基盤テストスイート設計（0.5日）
**目的**: アクセシビリティ要件の自動テスト戦略を策定
**作業内容**:
- axe-core または podobなアクセシビリティテストツールの選定
- キーボードナビゲーションテストケース設計
- スクリーンリーダー対応テストケース設計
- 色コントラスト比テスト（WCAG 2.1 AA/AAA 基準）
**成果物**:
- `tests/accessibility/` ディレクトリ構成設計
- テストシナリオドキュメント

### ステップ 8: キーボードナビゲーション自動テスト実装（1日）
**目的**: キーボード操作の自動テストを実装
**作業内容**:
- Playwright または Selenium ベースのキーボードナビゲーションテスト
- Tab 順序テスト（論理的なフォーカス移動）
- フォーカスリングの可視性テスト
- エンターキー・スペースキーでのボタンアクティベーションテスト
- ESC キーでのダイアログ・モーダル閉じテスト
**成果物**:
- `tests/accessibility/test_keyboard_navigation.py`
- CI パイプラインへの組み込み

### ステップ 9: 色コントラスト自動テスト実装（0.5日）
**目的**: WCAG コントラスト基準を満たしているかを自動検証
**作業内容**:
- 色コントラスト比計算ライブラリの導入（例: `wcag-contrast`）
- テキスト・背景色の組み合わせを全パターン検証
- プレースホルダー・無効状態などの特殊ケースも対象
- レポート生成機能（失敗ケースのハイライト）
**成果物**:
- `tests/accessibility/test_color_contrast.py`
- コントラスト比 4.5:1 (AA) または 7:1 (AAA) を基準とするアラート

### ステップ 10: スクリーンリーダー対応テスト実装（0.5日）
**目的**: スクリーンリーダーユーザーへの情報提供を検証
**作業内容**:
- ARIA ラベル・ロール・状態の存在テスト
- ライブリージョン（エラーメッセージ・ローディング状態）のテスト
- ランドマークナビゲーションの存在テスト
- 実際のスクリーンリーダー（NVDA, VoiceOver）での動作確認手順ドキュメント
**成果物**:
- `tests/accessibility/test_screen_reader.py`
- 手動テストチェックリスト

### ステップ 11: リグレッション防止のためのビジュアルテスト基盤構築（1日）
**目的**: ビジュアルリグレッションを防止するテスト基盤を構築
**作業内容**:
- Storybook または podobなコンポーネントカタログシステムの導入検討
- Percy または Chromatic などのビジュアルテストサービスの評価
- ローカルでのビジュアル差分検出ツール（例: `pixelmatch`）の設定
- ベースライン画像の管理戦略
**成果物**:
- `.storybook/` ディレクトリ（もしくは相当する構成）
- ビジュアルテスト設定ファイル
- ベースライン画像保存用ディレクトリ（`.visual-baselines/`）

### ステップ 12: コンポーネント別ビジュアルリグレッションテスト実装（1日）
**目的**: 重要コンポーネントのビジュアルリグレッションテストを実装
**作業内容**:
- ヘッダー・フッター・サイドバーのビジュアルテスト
- ボタン・フォーム要素の各状態（デフォルト・ホバー・フォーカス・ディセーブル・アクティブ）のテスト
- エラー・空状態・ローディング状態のビジュアルテスト
- レスポンシブブレークポイントごとのテスト（モバイル・タブレット・デスクトップ）
**成果物**:
- `tests/visual/test_header.py`
- `tests/visual/test_buttons.py`
- `tests/visual/test_forms.py`
- CI パイプラインへの組み込み（夜間実行または PR チェック）

## 成功基準
- すべてのハードコードされた色・スペーシング・フォントサイズがデザイントークンに置換されていること
- WCAG 2.1 AA 基準を満たすアクセシビリティ（コントラスト比 4.5:1 以上、フォーカスインジケータ表示）
- キーボードのみでアプリケーションの全機能が操作可能であること
- ビジュアルテストベースラインが確立され、意図しないUI変更を検知できること
- 新規コンポーネント追加時にトークンシステムを使用することが標準プロセスとなること

## 次フェーズへの引き継ぎ
- デザイントークンシステムが安定していること
- アクセシビリティテストがパスしていること
- ビジュアルリグレッションテスト基盤が構築済みであること
